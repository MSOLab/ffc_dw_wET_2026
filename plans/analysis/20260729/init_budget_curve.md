## 0. 질문

총 예산 `0.09nc` 중 초기화(MCF-LB → FMM → NEH-CP)가 쓰던 `0.036nc`(총예산의
40 %)를 **10 % / 20 % / 40 %로 줄이고**(총예산의 4 % / 8 % / 16 %) 앞에 거의
공짜인 v4 dispatch 초기해를 놓으면, 최종 RPDf 는 얼마나 손해/이득인가.

가설: **초기화에서 아낀 시간이 개선 tail 로 넘어가면 최종 RPDf 가 나빠지지
않거나 오히려 좋아진다.**

## 6. 판정

1. **주 판정(끝점).** f10/f20/f40 모두 기준선보다 나쁘지 않다. f40 은
   −1.085 %p (쌍대 SE 0.300 → 3.6 σ, 728승/564패)로 **유의하게 좋고**, f20 은
   −0.623 %p (2.0 σ), f10 은 −0.110 %p 로 **기준선과 구분되지 않는다.**
   → 초기화 예산을 총예산의 40 % → 16 % 로 줄이는 것은 무손해이며, 4 % 까지
   줄여도 최소한 손해는 아니다.
2. **곡선의 무릎.** 교란 없는 같은-run 비교에서 f10 → f20 → f40 은 **단조로
   좋아진다**(f40−f10 = −0.975 %p, 4.3 σ). 즉 측정한 4–16 % 구간에서는 예산이
   많을수록 좋고, 무릎은 16 % **이상**에 있다. 100 % 지점은 이번 run 에 없어
   (`dv4_c5init_f100` 은 이번 분석 대상에서 제외) 곡선의 오른쪽 끝은 판정하지
   않는다.
   → **가설은 측정 구간에서 지지되지 않는다.** "아낀 시간이 tail 에서 더 값지다"
   면 f10 이 f40 보다 좋아야 하는데 반대다. 다만 "초기화를 크게 줄여도 최종
   품질이 나빠지지 않는다"는 약한 형태는 성립한다.
3. **초기화 종료 시점의 손해와 회수.** neh_cp 시점에서 f10 은 기준선보다
   +13.1 %p 나쁘지만 시간은 0.080 vs 0.372 로 29 %p 를 tail 에 넘겼다. 이 손해는
   ISW-CP 첫 batch 전에 이미 회수되어, x ≈ 0.035 이후 세 곡선 모두 예산 소진까지
   기준선 이하를 유지한다. 계획 §7-3 의 "교차점이 x=1.0 이전이면 이득" 기준은
   충분히 만족한다.
4. **전치 dispatch.** §4 참조 — 21.8 % 의 instance 에서 MCF 유도해를 이겨 MCF
   직후 인컴번트를 2.53 %p 개선하고, 비용은 TL 의 1.2 %.

## 7. 한계 — 결론에 반드시 붙는 것

1. **전치 dispatch 혼입.** 기준선 대비 −1.085 %p 중 얼마가 초기화 예산 효과이고
   얼마가 전치 dispatch 덕인지 **분리할 수 없다**. 분리하려면
   `dv4_c5init_f100`(전치 + 초기화 100 %)이 필요한데 이번 분석 대상에서
   제외했다. §2 표의 세 Δ 는 "예산 효과"가 아니라 "예산 + 전치"의 합이다.
   같은-run 비교(§2 아래 표)만이 순수한 예산 비교다.
2. **코드 드리프트(부분적으로 경계 지어짐).** MCF-LB step 은 1440 전부 비트
   동일이므로 드리프트가 없다(§4). 그러나 `a72c3c4`(*keep incumbent on budget
   exhaustion*)는 마지막 `solve_base_model_cpsat` 끝점을 바꾸므로, 기준선 대비
   끝점 비교에는 여전히 드리프트가 섞여 있다. 같은-run 비교는 여기서도 자유롭다.
3. **CP-SAT 노이즈.** 8-worker wall-clock CP-SAT 는 비결정적이고, 1440 격자에서
   평균 obj ±350 이하는 노이즈다. mean obj 델타로 보면 f20(+246)은 노이즈 안,
   f10(+954)·f40(−1019)은 밖이다. RPDf 쌍대 SE 기준 판정(§6-1)이 더 정밀하며 두
   기준의 결론은 f40 에서 일치한다.
4. **평균 obj 와 mean RPDf 의 불일치.** f10 은 mean RPDf 로는 기준선과
   비슷한데(−0.110 %p) mean obj 는 +954 만큼 나쁘다 — 목적값 평균은 대형
   instance 가 지배하기 때문이다. §5 의 크기 셀이 그 출처를 보여준다
   (`n=150, c=5` 등). 초기화 축소의 위험은 **대형·빡빡한 instance 에 국소적**이다.

## 8. 결론

> 초기화 예산을 총예산의 40 % → 16 %(`f40`)로 줄이면 최종 RPDf 가 **−1.09 %p
> 좋아지고**(728승/564패, 3.6 σ), 4 %(`f10`)까지 줄여도 기준선과 구분되지 않는다.
> 다만 교란 없는 같은-run 비교에서는 f10 < f20 < f40 로 **예산이 많을수록 좋아**,
> "아낀 시간이 tail 에서 더 값지다"는 가설은 4–16 % 구간에서 성립하지 않는다.
> 무릎은 16 % 이상이며, 손해는 T=0.6·R≥0.6 과 중대형 c=5 셀에 국소적이다.
> 전치 v4 dispatch 는 21.8 % 의 instance 에서 MCF 유도해를 이겨 초기 인컴번트를
> 2.53 %p 개선하며 비용은 TL 의 1.2 % 다.

**다음 단계 후보** — 무릎이 16 % 이상이라는 것만 확인됐으므로, 곡선의 오른쪽
(f60 / f80 / f100)을 같은 run 안에서 재면 예산-품질 곡선이 닫힌다. 그 run 에
`dv4_c5init_f100` 을 넣으면 §7-1·§7-2 의 두 교란이 동시에 사라진다.

## 1. 질문

> τ=1 CSR initializer가 총 예산(`0.09nc`)의 **40 % 이하**를 쓰면서, 기존
> initializer `best(MCF-LB → FMM, NEH-CP)`를 **9개 (T,R) 셀 전부**에서 이기는가?

```
PASS(f)  ⇔  ∀ (T,R) ∈ 9셀 :  meanRPDf(csr_init_tau1_f) ≤ meanRPDf(c5_init_only)
게이트   ⇔  ∃ f ≤ 40 % : PASS(f)
```

양쪽 arm 모두 tail이 없으므로 이것은 **초기해 품질** 비교다. 최종해에 대한 함의는
없다(§7).

## 4. 예산 준수 실측 (2급-1)

| 시나리오 | mean elapsed (s) | / `0.09nc` |
|---|---|---|
| `c5_init_only` | 32.01 | 37.19 % |
| f=20 | 15.87 | 18.95 % |
| f=25 | 19.68 | 23.51 % |
| f=30 | 23.51 | 28.09 % |
| f=35 | 27.33 | 32.67 % |
| f=40 | 31.16 | **37.25 %** |

두 가지가 확인된다.

1. **예산 초과는 없었다.** 계획서 §1.1이 "MCF-LB 중단 불가로 양쪽 다 초과할
   것"이라며 무시하기로 했던 항목인데, 실측은 반대다 — 명목 40 %인 두 arm이 모두
   37.2 %로 **미달**이다. `adb8e60`(라운드 1 원자화) 이후 mcf_lb 비용이 ~2.0 s로
   안정된 것과 정합한다. 따라서 이 비교는 **예산 초과 보정 없이 그대로 읽어도
   된다.**
2. **f=40과 C5는 예산이 사실상 동일하다** (31.16 s vs 32.01 s, 37.25 % vs
   37.19 %). 계획이 의도한 "동일 예산 상한에서의 initializer 대결"이 실측으로
   성립했다. 그 조건에서 CSR이 pooled −17.18 pp, 9/9 셀 승리다.
3. **f=20은 C5의 절반 예산이다** (15.87 s vs 32.01 s). 즉 **절반 시간으로 9셀 전부
   승리**한다.

## 6. 내부 단계 궤적 (2급-3) — W3의 f를 여기서 고른다

W1(`2c7ef28`)의 inner-point 라벨링 덕에 CSR 한 스텝 안의 4단계를 시간·개선량으로
분해할 수 있다 (1440 인스턴스 평균, `inner_steps.csv`):

| f | mcf_lb | flip | neh_cp | isw batch | 계 |
|---|---|---|---|---|---|
| **시간 (s)** | | | | | |
| 5 | 1.9 (46 %) | 0.5 | 1.4 | 0.4 (8 %) | 4.2 |
| 20 | 2.0 (12 %) | 1.7 | 5.2 | 6.9 (44 %) | 15.9 |
| 40 | 2.0 (7 %) | 3.1 | 9.5 | 16.0 (52 %) | 31.2 |
| **목적함수 개선량** | | | | | |
| 5 | (초기해 생성) | 1,526 | 1,212 | 2,544 | 5,282 |
| 20 | (초기해 생성) | 2,134 | 4,250 | 13,657 | 20,041 |
| 25 | (초기해 생성) | 2,223 | 5,187 | 14,049 | 21,459 |
| 30 | (초기해 생성) | 2,368 | 5,968 | 14,504 | 22,840 |
| 40 | (초기해 생성) | 2,520 | 7,286 | 14,822 | 24,628 |

읽는 법 세 가지:

1. **`mcf_lb`는 f에 무관한 고정비용 ~2.0 s**다. f=5에서 46 %, f=40에서 6.6 %.
   §3.2의 절벽이 여기서 나온다 — 작은 f에서는 이 상수가 예산을 잡아먹는다.
2. **isw batch 단계가 개선의 대부분을 산다**(f=20에서 20,041 중 13,657 = 68 %)
   **그러나 f=25 이후 포화된다**: 14,049 → 14,504 → 14,822, 즉 f를 25→40으로
   **60 % 늘려도 개선은 5.5 %밖에 안 는다**. 이 단계에 추가 예산을 주는 효율은
   f=25 부근에서 꺾인다.
3. **포화되지 않은 것은 `neh_cp`뿐이다**: 4,250 → 5,187 → 5,968 → 7,286으로 f에
   거의 선형이다. f≥25에서 곡선이 계속 내려가는 것은 사실상 neh_cp의 몫이다.

f=15부터 `solve_base_model_cpsat`가 내부 점으로 극소수 등장하나 시간·개선량이 모두
~0이다(내부 flow가 예외적으로 끝까지 간 인스턴스). 판독에 영향 없음.

**pooled RPDf의 한계효용** (+5 %p당): f20→25 −1.76, 25→30 −1.45, 30→35 −0.48,
35→40 −0.92 pp. **f=30 이후 뚜렷이 둔화**하지만 완전히 평평해지지는 않았다.

> **W3 권고: f = 25 % 또는 30 %.** 게이트를 여유 있게 통과하는 최소 예산이면서
> (최약셀 −2.87 / −4.18 pp), isw 포화점 바로 위이고, tail에 70–75 %의 예산을
> 남긴다. f=40은 초기해로는 가장 좋지만 tail 예산을 37 %나 먹으므로 W3의 목적
> (CSR init + isw tail + base CP-SAT의 **최종해**)에는 과투자일 가능성이 높다.

## 7. 결론과 그 한계

**결론: P1 게이트 통과.** τ=1 CSR initializer는 예산의 20 %만 써도 9개 (T,R) 셀
전부에서 C5 initializer 이하의 RPDf를 내고, 동일 예산(37 %)에서는 pooled
−17.18 pp에 1227/132/81로 이긴다. 로드맵 §2의 "게이트를 통과하는 것은 τ=1 CSR뿐일
가능성이 높다"는 예상이 확인됐다.

**함의의 범위** — 계획서 §5가 미리 못 박은 대로:

- 이것은 **초기해 품질**만 잰다. `csr_init_isw_batch_result.md`에서 초기해
  13.15 pp 우위가 파이프라인 통과 후 ≤1.16 pp로 수축한 전례가 있다. 여기의
  −17.18 pp가 최종해에서 얼마나 남는지는 **W3가 잰다.**
- 게이트는 **τ=1**에 대한 판정이다. 로드맵 §1의 "τ>1은 가치 없음"은 변하지 않으며,
  이 결과는 τ>1 end-to-end 측정의 착수 근거가 **아니다** — 통과한 것은 coarsening이
  아니라 "coarsening 없는 CSR 껍데기"다.
- 20260714 곡선과는 **겹쳐 읽지 않았다**(계획서 §1.2의 코드 드리프트 4건). 형태만
  말하면 두 곡선 모두 f에 단조 개선이고 상단에서 둔화한다.
